Šta se analizira

Algoritam ili program · vrijeme i prostor · analiza koda i mjerenje programa.

3

Algoritam ima ulaz, izlaz i kraj; analiziraju se vrijeme i prostor

Karakteristike algoritma

ulaz: nula ili više · izlaz: najmanje jedan

Primjer bez ulaza s predavanja: generisanje svijeta igre iz fiksnih pravila.

određenost: daje traženi odgovor, a ne bilo kakav

konačnost: ne vrti se beskonačno bez izlaza

efikasnost: izvodljiv i upotrebljiv

Pseudokod

algoritam se piše bez tipova i detalja jezika

Analiza ne zavisi od toga da li je kod u C++, C# ili Pythonu.

Šta se mjeri

vrijeme: koliko traje izvršavanje · prostor: koliko memorije zauzima

u praksi i: mrežni promet · potrošnja energije · registri procesora

Navedeno na predavanju; u ovom predmetu samo vrijeme i prostor.

Jedinica

jedan korak = jedna osnovna operacija (dodjela, poređenje, aritmetika)

Ne mjeri se u ns: isti korak na različitim procesorima traje različito.

02

Brojanje koraka

Svaka linija dobije broj izvršavanja · zbir je T(n) · zadržava se najveći stepen.

6

Bez petlje: broj koraka ne zavisi od ulaza, pa je vrijeme konstantno

Prostor

temp, a, b: 3 jedinice (nezavisno od arhitekture)

Konstantno vrijeme

T = 3 ili T = 4 → O(1)

Za 2 elementa ili za milion poziva, jedan poziv uvijek ima isti broj koraka.

Isto kod naših struktura

StekSekv::push · StekPov::pop · RedSekv::dodaj · RedPov::ukloni

Nemaju petlju: nekoliko dodjela i jedna provjera.

S predavanja (za zagrijavanje)

swap bez treće varijable: a ^= b · b ^= a · a ^= b

XOR: i dalje O(1) vremena, ali 2 jedinice prostora umjesto 3.

7

Suma niza: T(n) = 3n + 4, pa je red veličine n

vrijemeprostor
zbir1 + 1 + (n + 1) + n + n + 1 = 3n + 4a: n · n, s, i: 3 → n + 3
red veličineO(n): zadržava se najveći stepenO(n), ali niz je ulaz; algoritam dodaje O(1)

Zašto n + 1

i = 0, 1, …, n − 1 prolazi · za i = n uslov je netačan i petlja staje

Zaokruživanje

3n + 4 → n: konstante i niži stepeni se izostavljaju

Za n = 10⁶: 3.000.004 koraka; dvostruko veće n daje dvostruko više koraka.

Prostor ne raste s algoritmom

za 2000 elemenata isti s i i kao za 1000

Raste samo ulaz (niz), a ne ono što algoritam alocira.

Pitanje

koliko koraka ima suma za n = 0?

s = 0, i = 0, jedno poređenje, return: T(0) = 4.
